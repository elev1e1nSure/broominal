---
name: auto-docs
description: Sync project documentation with the actual codebase when code changes make docs outdated. Use after adding or changing commands, public APIs, configs, packages, screens, workflows, features, or behavior that should be documented.
---

Review the current codebase and all documentation files.

Find docs such as README files, AGENTS.md, docs directories, changelogs, usage guides, config examples, architecture notes, and CLI help references.
Update only documentation that is stale, incomplete, or inconsistent with the implemented code.
Cover changed commands, flags, public behavior, configs, packages, workflows, screens, categories, risks, examples, and tech stack when relevant.
Do not invent features, remove valid information, or rewrite docs unnecessarily.
Keep translated docs structurally aligned with their source docs when applicable.
Verify edited docs for stale references, placeholders, broken markdown, outdated examples, and mismatched behavior.
Report briefly which docs changed and why.
